# Družina — verified public leaderboard (Work automation interface)

**As of 2026-10-19:** Public UI and privacy-safe export code are staged. No actual verified participants have been submitted: public snapshot deliberately contains zero names, portraits or scores. **Unattended sync is NOT yet connected.** Do not represent this as automatic live membership tracking.

## Single source of truth
The existing private Community Hub `events-registrations-template` Sheet ID `1igxEHQ7wFFCoCA9lg4kzT2OoMrVLgbBogfqTxGeUftY` has already-created tabs:
- `Druzina_Public_Profiles` (18 columns A:R). Public name, separately reviewed opt-in for stats/awards/photo, adulthood classification, proof, approval and revoke/expiry. This does **not** take data from `Druzina_Members` publicly by default.
- `Druzina_Achievement_Evidence` (16 columns A:P). One *real attended event* or *verified service event* per row with event ID/date, type, track, evidence reference, independently verified-by/date, unique key and approval. Do not infer attendance from a paid booking, RSVP, calendar slot, package invoice, LARP interest or event signup.
- `Druzina_Leaderboard_Publish_Log` (10 columns A:J). Publish attempts and SHA-256 for audits; owner/Work integration must write here after a real verified release.
- Existing `Druzina_Bookings`/`Druzina_Sessions`/`Druzina_Pesak_Progress` are **not** reliable public attendance right now. Check-in must be entered and confirmed by an authorised instructor/organiser first.

## Authorisation gate
Publicly list adults 18+ only when `Age_Class=ADULT`, `Name_Opt_In=TRUE`, `Stats_Opt_In=TRUE`, `Awards_Opt_In=TRUE`, `Visibility_Status=PUBLIC_APPROVED`, proof/approval dates and approving person exist, and no revocation/expiration is active. For portraits also require `Photo_Opt_In=TRUE`, a separately approved photo path, and an approved image uploaded only into `druzina/leaderboard/images/portraits/` (safe basename .webp/.png/.jpg). Public source data never contains Member_ID, email, phone, guardian details, evidence, payment, health, WhatsApp messages or legal consent references. Do **not** automatically list minors even if guardian agrees: a separate child-safe private progress view should be developed later.

## Activity evidence
Only rows with `Verification=VERIFIED`, `Approved_For_Count=TRUE`, `Verified_By`, `Verified_At`, `Proof_Ref`, `Unique_Key` and valid completed event date count. Duplicate member/event/type suppressed. Accepted canonical `Event_Type` = `TRAINING`, `ARCHERY`, `BATTLE`, `VOLUNTEER`, `MENTOR`. Approved ARCHERY also counts as one general training. Monthly categories: training count, battle visits, archery sessions, total verified volunteer minutes, mentor sessions and different ISO weeks of verified training/battles. This is participation only, never "best fighter skill", official rank, purchase, training level, or mandatory volunteering.

## Machine / ChatGPT Work hand-off
The existing Work agent is the upstream attendance-verification owner; **do not create a second membership spreadsheet or overwrite the owner’s records**. When the agent verifies a real attendance record, it writes once to `Druzina_Achievement_Evidence`; when a person/guardian changes preference, it updates `Druzina_Public_Profiles` and applies revocation immediately. The site file is generated by `scripts/druzina_leaderboard_export.py`, target `druzina/leaderboard/results.json` in **growth-experience** (GitHub Pages source branch, *not* default main).

Read-only Google Sheets service-account scope `spreadsheets.readonly` and secure credentials provision are a pending owner/Work setup task. Never put a Google credential, sheet export or raw attendee source into git, GitHub issue, Page HTML, or public JSON. Run `python -m unittest discover -s tests -p 'test_druzina_leaderboard.py' -v`, validate preview, publish only the sanitized diff, record SHA/date/outcome in `Druzina_Leaderboard_Publish_Log` and inspect live site. If no eligible consent/evidence, publish an empty legitimate snapshot and no award nominees. If unable to authenticate or validation fails, retain last safe public snapshot **and show delayed/pending status**, never fall back to public full CSV.

Illustrative local invocation AFTER securing credentials (not run from public repo):
`python scripts/druzina_leaderboard_export.py`

## Publication and contest fairness
Do not create monetary incentives for high-risk sparring, ranking kids against adults, unverified public "fighter of month" skill awards, fictional mentoring attendance, attendance fraud or retroactive rank upgrades. Keep all regular classes voluntary and accessible regardless of public opt-in. The certified first-visit/archery supervision and legally paused HEMA paid-sale gates remain unaffected. Insurance summary belongs on `/druzina/safety/` and must retain policy limits and exclusions.
