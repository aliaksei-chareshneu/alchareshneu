3. User chooses a first visit, single visit, a package and the package's eligible session dates. Show price calculated from **server-side** product table; do not accept browser-supplied amounts or member tier. Price is calculated for each session date, with immutable version and snapshot.

At payment commitment/receipt, recompute all prices and T-48 from **server time** and verify capacity under lock. **A hold does not freeze the 48-hour deadline.** Do not create orphaned paid obligations if rate changed; re-quote and obtain fresh explicit approval, or refund/exception if a payment arrived too late. The currently connected Stripe account `Buymeacoffee` is NOT established as Družina z. s.'s merchant; **do not charge it for z. s.** Consider Comgate as a card-gateway alternative after verifying supported seller entity, actual tariff and contract.

A trusted Stripe signature or read-only Fio bank CREDIT must match correct merchant, exact amount, CZK and unique variable symbol, and must be applied idempotently.

Only once verified, and only after all per-session legal/safety/capacity/guardian gates pass, atomically create the booking and package schedule in **existing** Družina private tabs, debit the right number of package sessions, send payment receipt, and update private member view. 8. The Community Google Calendar stores one organizer event per actual session (with original event IDs). Do **not** create a duplicate public event for every participant. Add one private calendar invitation / ICS or user-authorized Google Calendar add-link for each confirmed, correctly paid booking; use a private admin roster, never attach a public guest list exposing participants' emails. ## Server price policy: no hidden debt and no late package loophole
The new **pure** Apps Script-compatible source `DruzinaBillingPolicy.gs` contains `drubQuoteItem`, `drubAuthorizeCheckout` and `drubMatchBankTransfer`, with `tests/druzina-payment-policy.test.cjs`. This source performs **no writes, no transfer, and no bookings** and is not imported into the existing Apps Script yet.

- **Before T-48h**: regular rate or a package covering only selected eligible future sessions. A package can be purchased anytime, but no covered date can be inside T-48 at booking commit. Existing contractual packages are respected.
- **T-48h through T-3h**: one upfront **Late Flex, +25%**, never added as a debt after attendance; no package session or first visit. October rates: Junior 300 Kč, Senior 150 Kč. Future November (not active) rates: Junior 300 Kč, Senior 250 Kč.
- **T-3h through before T-30m**: existing, previously verified participants only; **Emergency Flex, +50%**, subject to fully paid status and capacity. Future November: Junior 360 Kč, Senior 300 Kč.
- **At/beyond T-30m**: closed. There is no on-site walk-in bypass. Each late booking must be paid in full upfront, with no later 25% demand.
- Future November First Visit 240 Kč **before T-48h only**; Starter4 800 Kč for four selected sessions/30d. A **verified, actually attended and paid** 240 Kč first visit can be upgraded once within 48h *after attendance* by paying 560 Kč for the **three** remaining qualifying sessions; 30d runs from original first attended visit. Source preserves October 120 Kč trial rate and historic rights. Long packages listed publicly (12, 24, Unlimited) are **not activated** by this PR; they require final product snapshots, contracts, capacity and validity rules.
- Senior eligibility is earned by four **verified attended** sessions in month M and applies in month M+1, not immediately on the fourth booking. Organizer-caused cancellations can preserve status only on documented exception.

## Payment/API integration details
**Fio**: generate a *read-only* `Sledování účtu` token inside the authorized seller's online banking (never paste a token into chat/source). Configure in existing secure Apps Script Script Properties, verify token belongs to the intended payee, then poll GET transactions. A separate Fio token with payment rights is **forbidden** for this automation. Normalize bank movement transaction ID, variable symbol, positive settled CZK amount, actual receiving account and reversal state. Match inside a lock against one existing `Druzina_Quotes` / `Druzina_Payments` reference; unmatched or over/underpayments -> manual exception. Never trust a bank transfer screenshot as settled. Do not put account secrets in web pages or the public repository. Fio API is free per official bank description; actual bank transfer fees depend on the payer.
**Stripe**: once a correctly-verified OSVČ/z.s. Stripe account is connected and explicitly approved for this seller, use a server-created **hosted Checkout Session** with fixed quote snapshot (amount and currency CZK), customer identity session binding and timeout. A separate Supabase Edge Function can receive raw signed Stripe webhooks `checkout.session.completed` and delayed `checkout.session.async_payment_succeeded`; use Stripe-Signature verification, event/checkout/payment-intent idempotency, proper payout owner, status `paid`, exact currency and amount before recording the matching payment. Redirect success URL is **not payment proof**. Do not start live webhook until signing secret and a safe mirrored CRM write/lock are verified. No secret key on GitHub Pages. Card gateway fees are a separate trade-off from free Fio retrieval.
**Google Calendar**: use the existing shared Community calendar for schedule status, avoid public private roster. New private participant appointment only after paid booking and opt-in. Keep `CALENDAR_SYNC_ENABLED=FALSE` until a tested implementation with stable remote IDs, no duplicates, no leaked email list, and cancellation/refund corrections.
**Privacy**: only controller-specific PII, avoid mixing OSVČ and z.s. books; authenticated read-once profile, separate parental authorization, minimal retention and deletion mechanisms, no private data in front-end embeds or public GitHub.
